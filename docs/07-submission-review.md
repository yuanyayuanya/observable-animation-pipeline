# 最终提交审查与演示指南

## 1. 给评审者的项目摘要

这是题目 D“任务管线可观测方向”的单机可运行 MVP。项目刻意不实现真实大模型，而把工程重点放在耗时 AI pipeline 最容易出问题的部分：持久化状态、步骤级执行历史、自动与人工重试、Worker 中断恢复、并发租约、缓存复用、产物校验和可观察界面。

核心判断不是“生成的动画有多复杂”，而是：任务失败或进程消失以后，系统是否知道发生了什么，能否从正确边界恢复，以及是否会重复计算或覆盖正确结果。

## 2. 十分钟审查路径

建议按下面顺序查看，不需要先阅读全部源码：

1. 阅读 `README.md`，确认启动方式和运行目录。
2. 阅读 `docs/02-architecture.md`，查看 API、Worker、SQLite 和 Artifact Store 的职责边界。
3. 查看 `app/pipeline/registry.py`，确认五步顺序、权重和最大尝试次数。
4. 查看 `app/db/models.py`，确认任务、步骤、attempt、事件、产物和资源租约均持久化。
5. 查看 `app/db/repository.py` 的领取、心跳、完成、失败、恢复和缓存提交事务。
6. 查看 `app/worker/runner.py`，确认 Worker 从数据库领取任务，而不是依赖进程内队列。
7. 运行全量测试，再按 `docs/06-stage3-acceptance.md` 演示正常、自动重试、中断恢复和缓存复用。
8. 最后阅读本文的真实失败与限制，判断实现是否诚实、可解释。

## 3. 初学者运行清单

### 3.1 第一次准备

在项目根目录创建虚拟环境并安装依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

正式运行目录建议位于 E 盘，`.env.example` 给出了本项目使用的环境变量。不要把 `.runtime` 放入最终源码压缩包。

### 3.2 启动

第一个 PowerShell 运行：

```powershell
.\scripts\run_api.ps1
```

第二个 PowerShell 运行：

```powershell
.\scripts\run_worker.ps1
```

浏览器打开：

```text
http://127.0.0.1:8000
```

顶部显示“API 已连接”后，选择视频、保持默认参数并点击“创建并运行”。如果没有现成短视频，可先生成示例：

```powershell
.\.venv\Scripts\python.exe scripts\generate_sample_video.py .runtime\temp\sample.mp4 --seconds 3
```

### 3.3 判断运行是否正确

- **成功**：任务状态为 `SUCCEEDED`，进度 100%，五步均成功或缓存跳过，最终 ZIP 可下载。
- **自动恢复中**：步骤为 `RETRY_WAIT`，旧 attempt 保留错误，稍后出现新 attempt。
- **Worker 已中断**：步骤暂时仍显示 `RUNNING`，但心跳停止；租约过期后旧 attempt 应变为 `LOST`。
- **需要人工处理**：任务为 `FAILED`，页面显示错误类型与失败步骤；符合条件时可点击重试。
- **缓存复用**：步骤为 `SKIPPED`，事件中出现 `cache_hit`。

## 5. 真实失败、根因与修复

### 5.1 pytest 默认临时目录不可写

- **现象**：第一轮测试有 3 项在创建临时目录时失败，另有 2 项通过。
- **根因**：pytest 使用 C 盘用户临时目录，与受限执行环境及项目的 E 盘空间约束冲突。
- **修复**：测试脚本把 `TEMP`、`TMP`、`APP_RUNTIME_ROOT` 和 `--basetemp` 指向 E 盘项目运行目录。
- **验证**：相同基础测试随后通过。
- **边界**：绕过 `scripts/run_tests.ps1` 直接执行裸 `pytest` 时，临时目录仍由本机环境决定。

### 5.2 继承系统包导致依赖冲突

- **现象**：首次安装 FastAPI 后出现 OpenTelemetry 依赖版本冲突警告。
- **根因**：为节省空间使用 `--system-site-packages`，形成了系统包与虚拟环境包混合的半隔离状态。
- **修复**：在 E 盘重建不继承系统包的虚拟环境，并固定兼容依赖范围。
- **验证**：干净环境完成导入并通过全套测试，pip 不再报告该冲突。

### 5.3 自动重试到期后空轮询一次

- **现象**：`RETRY_WAIT` 已到期，但 Worker 第一次轮询没有领取，第二次才领取。
- **根因**：SQLAlchemy Session 使用 `autoflush=False`，状态提升到 `READY` 后没有在查询前 flush。
- **修复**：在查询可领取步骤前显式 `session.flush()`。
- **验证**：`test_due_retry_is_claimable_in_the_same_poll` 断言到期重试在同一次领取调用中返回。

### 5.4 损坏缓存阻止重新提交

- **现象**：系统正确发现缓存哈希不一致，但重算后因为同名缓存目录仍存在而无法提交。
- **根因**：第一版只拒绝损坏缓存，没有先处理旧目录。
- **修复**：记录 `cache_invalidated`，把损坏目录原子移动到 `.runtime/quarantine`，再允许同键重算。
- **验证**：缓存损坏、隔离和重新提交均有单元测试。

### 5.5 页面打开但没有样式

- **现象**：首页能显示表单和文字，但浏览器使用默认样式。
- **根因**：HTML 静态资源地址与 FastAPI 挂载的 `/static` 路径没有对齐。
- **修复**：HTML 明确引用 `/static/styles.css` 和 `/static/app.js`，API 保持 `/static` 挂载。
- **验证**：UI 契约测试检查本地资源引用，首页、CSS 和 JavaScript 的 HTTP 请求均返回 200。
- **补充验证**：随后使用 Microsoft Edge 无头模式完成桌面与 390 像素窄屏真实渲染截图，样式加载正常且未发现内容重叠；截图保存在 `docs/images/`。

## 6. 第三阶段代码审查发现

这些问题是在阶段三审查中通过代码路径分析发现的，不伪装成线上事故：

- **任务列表总数错误风险**：分页响应的 `total` 不能等于当前页长度。现改为独立 `count_tasks()`，由 `test_task_list_total_is_not_limited_to_the_current_page` 回归验证。
- **GPU 资源租约提前过期风险**：仅续步骤租约会让长时间 AI attempt 仍持有步骤、却失去 `gpu:0`。现由心跳同步延长归属当前 attempt 的资源租约，测试验证新的心跳与到期时间。
- **文件已提交但数据库拒绝提交风险**：文件系统原子提交后若数据库因旧 lease 拒绝，可能留下无数据库记录的缓存目录。Worker 现在检查并隔离这种未跟踪缓存，由 `test_untracked_committed_cache_is_quarantined` 验证。

## 8. 仅与当前单机提交相关的限制

- 系统以 SQLite 和本地文件系统为事实来源，适合单机演示，不是多机生产调度器。
- 页面没有登录与多租户隔离，适合本机评审环境。
- Mock AI 和 Mock GPU 租约证明调度协议，不证明真实模型质量、显存管理或 GPU 利用率采集。
- 固定五步管线便于解释与测试，但不能由用户动态编排。
- 前端使用轮询；大量并发任务时需要更合适的事件分发机制。
- `.runtime/quarantine` 不自动永久删除，提交前应排除 `.runtime`，运行中则保留它用于故障取证。
