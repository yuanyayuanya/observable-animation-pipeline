# 阶段二实现记录

## 当前实现范围

阶段二把阶段一设计落成可运行的单机 MVP：

- SQLite WAL 数据模型、状态机和租约协议。
- 五个可独立重试的处理步骤。
- 基于 staging 和哈希校验的 Artifact Store。
- API、Worker 和恢复扫描器。
- 可观察任务、步骤、attempt、事件与产物的浏览器控制台。
- 单元、集成和端到端测试。

## 真实失败案例一：测试临时目录不可写

**现象：** 第一轮 `pytest` 中 3 个测试在创建临时目录时失败，另有 2 个测试通过。

**触发条件：** pytest 默认使用系统用户临时目录，当前受限执行环境无法访问该目录。

**根因：** 测试数据路径没有遵循项目已经确定的 E 盘运行目录约束。

**影响：** 测试逻辑本身未执行，容易被误判为代码错误；同时可能继续消耗紧张的 C 盘空间。

**修复：** 测试脚本显式把 `--basetemp`、`TEMP`、`TMP` 和 `APP_RUNTIME_ROOT` 指向项目下的 `.runtime`，并建议把项目放在空间充足的磁盘。

**验证：** 调整后同一轮基础测试全部通过。

**仍有限制：** 开发者直接运行裸 `pytest` 时，临时目录仍取决于本机环境；README 因此提供了推荐命令。

## 真实失败案例二：继承系统包造成依赖冲突

**现象：** 首次安装 FastAPI 成功，但 pip 报告 `opentelemetry-api` 与系统级 `opentelemetry-sdk` 版本不兼容。

**触发条件：** 为节省空间，第一次虚拟环境使用了 `--system-site-packages`，随后安装最新 FastAPI。

**根因：** 虚拟环境继承了 Anaconda 中已有依赖，同时又覆盖了其中一个传递依赖，形成半隔离状态。

**影响：** 当前项目可能可以启动，但环境不可复现，其他系统包也可能在运行期导入不兼容版本。

**修复：** 清空并重建 E 盘虚拟环境，不再继承系统包；同时把 FastAPI 固定在 `>=0.116,<0.117`，再安装完整项目依赖。

**验证：** 干净环境内完成导入并通过全套现有测试，pip 不再报告该冲突。

**仍有限制：** Windows 和 Python 大版本变化仍可能影响 OpenCV wheel；锁文件会在最终验收版本生成。

## 真实失败案例三：到期重试空转一次

**现象：** 步骤已经超过 `next_attempt_at`，Worker 的第一次轮询返回无任务，第二次轮询才领取成功。

**触发条件：** `claim_next_step` 在同一事务内先把 `RETRY_WAIT` 改为 `READY`，随后立刻执行 runnable 查询。

**根因：** Session 为了控制事务边界使用 `autoflush=False`，状态修改尚未写入 SQLite，后续 SELECT 仍读到旧状态。

**影响：** 不丢任务，但每次自动重试增加一个轮询周期；较长轮询间隔下会放大恢复延迟。

**修复：** 在提升到期重试后显式调用 `session.flush()`，再执行原子领取查询。

**验证：** 数据库回归测试和真实短视频自动重试端到端测试均要求同一次调用立即领取。

**仍有限制：** SQLite 适用于本题单机部署；多机扩展时应迁移 PostgreSQL 并使用其行锁语义。

## 真实失败案例四：损坏缓存阻止重新提交

**现象：** 缓存哈希校验失败后重新计算，Artifact Store 因同名缓存目录已存在而拒绝提交。

**触发条件：** 数据库缓存记录存在，但对应文件被修改或部分损坏。

**根因：** 第一版只判定缓存无效，没有移走旧目录。

**影响：** 正确地拒绝了损坏结果，却无法通过重新计算自愈。

**修复：** 记录 `cache_invalidated` 事件，并把旧目录原子移动到 `.runtime/quarantine`，随后允许同一缓存键重新提交。

**验证：** 单元测试覆盖损坏、隔离和同键重算；Worker 集成路径调用同一接口。

**仍有限制：** 隔离目录不会自动永久删除，便于面试演示和取证；长期运行系统应配置保留周期。

## 阶段二验收结果

- 自动化测试：`53 passed`。
- 正常任务：五步全部 `SUCCEEDED`，进度 100%，生成可下载 ZIP。
- 缓存重跑：第二条相同任务五步全部 `SKIPPED`，事件包含 5 次 `cache_hit`。
- 自动重试：`analyze_fail_once_at_50` 的 attempts 为 `FAILED, SUCCEEDED`，前置步骤各执行一次。
- 手动重试：预览图首次最终失败，API 重试后成功，下游打包继续。
- Worker 中断：进程在 AI 47% 真实退出；新 Worker 回收租约后 attempts 为 `LOST, SUCCEEDED`，任务最终成功。
- 并发与迟到提交：数据库测试证明同一步只有一个有效领取，旧 lease token 的提交被拒绝。
- 正式运行副本通过相同全量测试，健康接口、首页、CSS、JavaScript 和任务 API 均返回 HTTP 200。
